# 访客筛选口径

给下一班和编辑用。这里只写访客会碰到的取舍。排班时刻、抓取间隔、影子分、写池并发、内部编号都不是内容门，不要写进筛选说明，也不要印在公开页上。

信息架构仍是：信息精选、信息简讯、工具决策、实战手册、专题观察。

## 同一件事只进一个新闻或做法入口

信息精选、信息简讯、实战手册讲的不是同一批东西。同一件事只留一个栏目。

- 能照着做的步骤、做法和可复现的操作，只出现在实战手册。不要因为它也像一条新闻，再写进信息精选或信息简讯。
- 信息精选和信息简讯只放新闻、领域里的大事、行业动向和发展。这两栏仍然完全分开：同一件事只留一处。
- 工具决策仍按工具往后排。一件事如果既是工具又是新闻，可以同时留在信息精选和工具决策，方便决定要不要试。不要让信息精选、信息简讯、工具决策三处一起出现同一件事。
- 对照同一件事时看原文链接和同一条编号，不看标题像不像。「公开更新」这种套话标题不算同一条。

## 仍然要拦

- 广告和营销软文不上站。
- 同一件事不要在首页的不同栏目里各讲一遍。信息精选可以和工具决策同时留下；信息精选、信息简讯、实战手册之间不重复。
- 注入、乱码、没写完的待办、提示词和编辑脚手架不上公开站。
- 实战手册要能照着做：至少抽出两步具体做法。英文步骤仍然不上。
- 信息精选按硬门槛。某一上海日一条都没有时，用当天最强的一条工具或简讯顶上，只一条。不放宽多源门槛去凑第二条，也不把这条改成重磅。
- 实战标题写成访客能读的中文做法，不用推文里的状态句（例如「没想到搞好了」「跟大家同步」）。步骤还能照做时，改用做法当标题，不把整条丢掉。

## 折叠，不物理丢掉

太旧、热度低、新词少，都不再把一条本来合格的内容从池里删掉。状态写成 `deferred`（本期先不上），数据留在池里，长尾以后还能找到。不为折叠项另开一条首页通道。

- 同源短窗（默认 30 分钟）只在网址相同或标题相似时去重。新词少于 3 不再单独丢掉。
- 超过约 48 小时、没有可信发表时间、或回填进来的旧时间：折叠，不丢弃。强制优先项仍可回到待审，但不自动写公开页。
- 同一簇 7 天没有实质进展：折叠，不丢弃。折叠后的转载不拿来凑「已经核对」。
- 低质量和广告、重复、注入，仍然可以真正丢弃。

## 热度只排序

实战手册的收藏数只用来排序。收藏少，或前几个小时还没有计数，不能单独否决一条已经写清步骤的做法。

## 中文说清楚即可

标题、事实和影响要让访客读懂。机器翻译可以兜底。不要因为英文开源信号的中文还不够漂亮，就整条丢掉。

没写完的编辑脚手架、待办和内部流程用语仍然不上站。

## 每轮简讯

自动信息简讯每轮新发最多 18 条，保留也最多 18 条。宁可少而清楚。

公开简讯只写发生了什么、为什么值得看、对我有什么影响，并给一个原文链接。不要再追加「证据：官方原始信息」或「建议行动：持续观察」。

## 访客看见的说法

| 内部 | 页面上 |
|------|--------|
| 已核对的重点 | 重磅 |
| 其余可看的 | 快讯 |
| 还没核完 | 尚待核实 |
| 工具这一类 | 新工具 |
| 采纳、试用、值得采用、可以试用 | 推荐使用 |
| 评估、暂缓、需要评估、暂缓跟进 | 值得关注 |
| 一手原文 | 原文可以核对 |
| 多个来源对上 | 已经核对 |

页面不出现这些词：强制 P0、P0-待证、auto_brief、多源、分数档、候选编号。内部编号可以留在数据里供去重，不要渲染出来。

工具决策的旧四档键可以继续留在文件里，但必须是空的；新写入只用「推荐使用」和「值得关注」。
